## 6. 为什么这样做

1. **为什么用 `touristappid` 而不是让用户注册**：用户明确要求「不要为了本轮验证先去注册正式小程序」。`touristappid` 是开发者工具内置的测试号标识，写入后模拟器可正常编译运行。
2. **为什么改 IDE 配置而不是点界面**：命令行服务端口默认关闭，官方提示可交互输入 `y` 开启，但 `.bat` 在非 TTY 环境下读不到该输入（`winpty` 也失败）。改配置是等价的官方开关。
3. **为什么用 `cli auto` 而不是让用户手工导入**：`cli open` 会因 AppID 校验被拒，而 `cli auto --trust-project` 可跳过该环节并同时开启自动化端口，使后续全部验证可脚本化。

### 9.3 真机预览：未能完成（平台限制）

`cli preview` 与界面预览均被**微信服务端**拒绝：

```text
[error] { code: 10, message: '不存在此 AppID 请检查后重新输入 (code 10)',
          at exports.handleUpload ... at async exports.preview [as method] }
```

原因：预览需要把代码**上传到微信服务器**换取体验二维码，而服务器不接受游客测试号 `touristappid`。
这是**微信平台约束**，与代码、环境、工具链均无关，AI 无法绕过。

已尝试的替代路径及结果：

| 路径 | 结果 |
|---|---|
| `cli preview --qr-format image` | 服务端拒绝（code 10） |
| `cli open --appid touristappid` | 拒绝（AppID 校验） |
| `cli auto --trust-project` | ✅ 成功（但仅启动本地模拟器，不产生体验码） |
| 复用本机历史 AppID | ❌ 经核查全部是**微信官方插件市场的插件号**（wasmCodeSplit 等），非用户小程序 |
