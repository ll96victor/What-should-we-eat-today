## 4. 具体改动区域

### 4.1 数据与共享逻辑的生成（`tools/build-miniprogram.mjs`）

只做三件事，且每件都带断言：

1. `data/recipes.json` → `miniprogram/data/recipes.js`（对象字面量模块）
2. `data/foods.json` → `miniprogram/data/foods.js`
3. `nutrition.js` → `miniprogram/lib/nutrition.js`（ESM → CommonJS）

转换规则：

```text
^export function NAME   →  function NAME      （收集 NAME）
^export const NAME      →  const NAME         （收集 NAME）
文件末尾                →  module.exports = { 收集到的所有 NAME }
```

生成后**读回产物并解析**，与源 JSON 逐字节比对；断言菜谱 370 / 荤 188 / 素 40 /
食物 123 / 主食 10，与 `specs.md` 记录一致。

幂等性：产物不写入时间戳，两次运行结果字节一致。

### 4.2 业务逻辑的可测试分层（关键设计）

配置所依赖的三层分离，使纯逻辑可以在 Node 里被真正执行（而不是只做文本断言）：

| 模块 | 是否碰 `wx` | 能否在 Node 里跑 |
|---|---|---|
| `lib/menu.js` | ❌ 完全不含 | ✅ 直接 `require` |
| `lib/settings.js` | ❌ 完全不含 | ✅ 直接 `require` |
| `lib/store.js` | ✅ 唯一 | ❌（由 E 组源码断言覆盖） |
| `pages/*` | ✅ | ❌（由 F 组接线断言 + 用户真机覆盖） |

`menu.js` 与 `settings.js` 的所有函数都**显式收参、显式返回**，不持有模块级可变状态。

### 4.3 首页（`pages/index/*`）

- 打开即见一桌荤素搭配的菜，卡片可点进详情
- 「换一组」调用与 Web 版同源的 `pickMenu`
- 池子不足时显示明确报错并**禁用**换一组
- 健康与营养关闭时：`recompute()` 直接清空估算并返回，不做任何计算、不产生任何营养文案
- 健康与营养开启时：追加主食区与「这桌菜估算」（合计 + ÷ 人数的数学平均 + 覆盖率）
- **在桌的菜若已被新加的屏蔽词命中，会整桌重选**（否则会出现「屏蔽了鱼，桌上还有鱼」）

### 4.4 详情页（`pages/detail/*`）

菜名 / 分类 / 难度 / 简介 / 食材 / 做法 / 小贴士 / 来源。
营养区只在开关开启时出现，文案与 Web 版逐字一致。

来源链接改为「**复制链接**」（`wx.setClipboardData`）——小程序不能直接打开外部网页，
这一点在页面上如实说明，不假装能打开。

### 4.5 设置页与成员页（`pages/settings/*`）

设置页：每餐数量、屏蔽关键词、健康与营养开关；开关打开后再出现家庭成员入口、
本次用餐人数、每天通常吃几餐、日常饮食参考，以及底部的口径说明。

成员页：列表 + 每位成员**各自独立**的健康参考 + 新增/编辑**共用同一个表单** +
删除两步骤确认 + 启用停用 + 上限 8 位。

### 4.6 存储

`lib/store.js` 是唯一调用 `wx.setStorageSync` / `wx.getStorageSync` 的地方，
键名与 Web 版完全一致：`what-should-we-eat-today.settings`。
读取容错沿用 Web 版语义：逐字段回退默认值、老 `healthProfile` 迁移、损坏数据不抛异常。

## 5. 为什么这样改

1. **不改 Web 版**（用户硬约束）。核查后确认技术上没有必要：`nutrition.js` 是零宿主依赖的
   纯函数模块，可直接转换复用；随机与屏蔽逻辑约 150 行，等价移植的成本可控。
2. **数据用构建生成而不是手工复制**。小程序读不到仓库外的文件，必须把数据复制进小程序目录；
   手工复制会造成第二份事实源，所以让脚本生成，并用断言把「同源」变成可自动验证的事实。
3. **转 CommonJS 而不是赌 ESM**。小程序对 `import/export` 的支持，检索到的资料互相矛盾；
   CommonJS 无争议，且转换规则机械、可断言、可回归。
4. **纯逻辑与宿主接口分离**。这是让 56 条断言能真正跑起来的前提——
   如果业务逻辑和 `wx` 调用混在一起，就只能做文本断言，价值低得多。
5. **营养文案逐字沿用**。三概念分离（每日能量参考 / 这桌菜估算 / 实际摄入）是硬性语义，
   迁移时重新措辞最容易走样，所以一个字都不改。
