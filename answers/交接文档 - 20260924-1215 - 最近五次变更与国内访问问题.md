## 五、本轮新发现：关于"数据来源于另一个 GitHub"

### 5.1 用户的观察

> "GitHub 那个版本的网站可以打开，但网站里的数据也是来源于另一个 GitHub。
> 不知道为什么，可能加载比较慢。这就是个问题，因为我的数据不是国内网络可以访问的。"

### 5.2 实测结论：**数据并非来自外部 GitHub**

用真实浏览器打开线上站点，抓取页面**全部资源请求**：

```
总请求数: 5
按域名统计: { "ll96victor.github.io": { n: 5, bytes: 291471 } }
外部请求: []          ← 零外部请求
```

**页面加载的全部 5 个资源（含数据）100% 来自站点自身域名，没有任何对外部 GitHub 的请求。**

数据加载方式（`app.js`）：

```js
const RECIPES_URL = 'data/recipes.json';
const FOODS_URL   = 'data/foods.json';
fetch(RECIPES_URL, { cache: 'no-cache' })
```

→ **相对路径**，随站点一起部署，**运行时不访问 GitHub**。

### 5.3 那 GitHub 链接是什么？

`data/recipes.json` 里 370 道菜**每道都带** `sourceUrl` 指向
`github.com/Anduin2017/HowToCook`（开源菜谱项目），用途在 `app.js`：

```js
`<p>来源：<a href="${recipe.sourceUrl}" target="_blank">${recipe.sourceName}</a></p>`
```

→ 这是**菜谱详情页底部的「来源」标注链接**（文字溯源），
**用户主动点击才会跳转**，不参与页面加载。

### 5.4 但用户的直觉方向是对的：真正的问题在托管平台

**整个站点（含数据）托管在 GitHub Pages**。`github.io` 域名在国内的连通性
长期不稳定（DNS 污染 / 限速），移动网络下体验可能更差。

**本机实测（仅供参考，不代表用户手机网络）**：

| 目标 | DNS | 连接 | TLS | 首字节 | 总计 |
|---|---|---|---|---|---|
| GitHub Pages | 0.058s | 0.158s | 0.366s | 0.641s | **0.651s** |
| CloudBase | 0.120s | 0.134s | 0.171s | 0.523s | **0.585s** |

### 5.5 另一个客观事实：数据文件偏大

| 资源 | 原始大小 |
|---|---|
| **`data/recipes.json`** | **735 KB** ← 占全站 84% |
| `app.js` | 47 KB |
| `styles.css` | 28 KB |
| `data/foods.json` | 26 KB |
| 其余（html/nutrition/图标/封面） | 约 37 KB |
| **合计** | **约 875 KB**（未压缩） |

移动网络下 735 KB 的 JSON 需要实打实下载，**这是"加载慢"的另一个独立成因**，
与托管平台无关。

## 六、可供规划 Agent 分析的事实清单

1. **站点完全同源**，无任何外部依赖 → 换托管平台**不需要改代码**。
