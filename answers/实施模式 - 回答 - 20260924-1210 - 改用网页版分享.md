## 6. 为什么这样做

1. **为什么用网页版而不是小程序体验版**：两者都免费，但体验版**仅限 15 名体验成员**、
   每加一个人都要管理员扫码、对方还得先被加进名单——那是"熟人内测"，不是"分享给好友"。
   网页版**不限人数、对方点开即用、无需注册**，符合用户"分享给好友免费用"的诉求。
2. **为什么改 `index.html` 而不是加分享按钮**：网页在微信里转发用系统自带入口即可，
   不需要自建按钮；缺失的只是"卡片长什么样"。补 `og:` 标签是最小改动。
   这也延续项目既有口径——分享一律走原生能力，不自建按钮。
3. **为什么封面图不另做设计**：用户先前明确要求"不要擅自设计一套新的品牌资料"。
   `assets/favicon.svg` 是项目**已有**素材，本轮只是**转格式 + 放大**，
   图案一笔未改（仅去掉圆角，因分享缩略图由平台裁切成方形，四角透明会显示异常）。
4. **为什么不删小程序转发代码**：认证是"将来可能改变的主意"，代码本身已通过全部断言。
   留着 = 将来一旦认证，功能立刻可用，零改动成本。

## 11. 后续建议

1. **请你实测一次**：在微信里把链接发给自己或好友，看卡片样式、看能否正常打开。
   这是唯一能确认 U1/U2 的方式。
2. **若要在 CloudBase 上也生效**：跑 `node tools/deploy-cloudbase.mjs what-should-we-eat-d0cym0b8ea64c`
   （需要 `tcb login`）。注意 CloudBase 默认域名有"页面访问提示"警告页，
   微信内多一次点击，体验不如 GitHub Pages。
3. **若将来绑定自定义域名**：记得同步更新 `index.html` 里的 `og:image` 与 `og:url`。
4. 小程序端转发代码保持原样；若哪天决定做认证，无需改代码即可恢复。
