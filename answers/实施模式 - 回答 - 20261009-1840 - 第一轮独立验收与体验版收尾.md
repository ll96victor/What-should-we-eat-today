## 3. 核对明细与四个用户应知事实

### 3.1 数量账（370 → 257）

消失 113 道，逐道有理由，0 道"说不清为什么没了"：
整类排除(aquatic) 28 + 词命中 23 + 强制排除 3 + 白名单未勾选荤菜 59 = 113。

### 3.2 事实一：素菜是 40 → 39，不是"39 全留"

执行 Agent 报「素菜 39 道全留」，与文档口径数字恰好相同，**掩盖了一个事实**：
裁剪前素菜是 **40 道**，「炒茄子」因食材表含**虾皮（主配料，非可选）**被忌口词命中排除。
判定：排除**正确**（虾皮是真海鲜配料，不是误杀），但"39 全留"的表述应改为
"素菜 40 道中 39 道保留，炒茄子因含虾皮按忌口排除"。若用户想吃无虾皮版炒茄子，
应走「强制保留的菜」并附理由（待用户决策，不擅自加）。

### 3.3 事实二：fail-closed 16/16，硬约束②成立

关键例：删「排除食材.海鲜」整组 → 构建失败并中文报错（不会静默放回全部海鲜菜）；
清空词表 → 失败；删文件/写坏 JSON/缺键/混入数字 → 失败；BOM → 容错成功（方向相反的非恒真例）。
所有失败例中 `data/recipes.json` md5 不变、`tools/.cache/last-parsed-names.json`（运行态派生基线）md5 不变——
**失败退出全部发生在写产物(766 行)与写基线(816 行)之前**，设计顺序正确。

### 3.4 事实三：白名单没有越界到其它 6 类

消失的非荤菜 9 道（炒茄子、电饭煲三文鱼炊饭、火腿饭团、鲣鱼海苔玉米饭、韭菜盒子、
螺蛳粉、温泉蛋、鲜肉烧卖、扬州炒饭）**全部**有忌口层理由（词命中/强制排除），
没有一道是白名单砍的——硬约束①的"白名单只作用 protein"成立。
其中火腿饭团（食材含海苔碎）、扬州炒饭（含基围虾）、韭菜盒子/鲜肉烧卖（含虾仁）、
麻辣香锅（食材写了鱼丸，可选）属"保守排除"：食材表字面命中即排，宁严勿松；
用户若想保留个别菜（如做麻辣香锅时不放鱼丸），走「强制保留的菜」附理由即可。

### 3.5 事实四：代码里 7 处忌口词字面量，均不参与匹配

执行 Agent 说"代码里没有任何忌口词"字面不成立。逐处人工核实（允许清单已写入验收脚本 §8）：
