## 4. 为什么这样改（关键取舍）

### 4.1 fail-closed 的实现边界

| 失效场景 | 行为 | 证据 |
|---|---|---|
| 规则文件缺失 | 构建失败，中文报「找不到」 | §7-§8-1 |
| JSON 语法坏 | 失败，报「不是合法 JSON」+ Node 位置 + 常见原因 | §7-§8-2 |
| 缺顶层必需键 / **缺必需分组** | 失败，报具体键路径 | §7-§8-3a/3b |
| 核心词表为空数组 | 失败 | §7-§8-4 |
| 白名单缺「菜名」/「启用」/ 空数组 | 失败，并提示「关白名单请改 启用:false，别删文件」 | §7-§8-10 |
| **文件带 BOM** | 构建**成功**（容错，非 fail-open） | §7-§8-5 |

**规划 §8-3 要求「删掉必需键（如 `排除食材.海鲜`）→ 失败」。** 实现时发现：若只校验「每个存在的分组是非空数组」，删掉**整个分组**不会报错——那会让该类忌口**静默失效**（例如删掉「海鲜」→ 全部海鲜菜回到池子）。因此补了**必需分组**校验：分组名（`海鲜`/`内脏`/`血制品`/`海藻`）属**文件结构（schema）**，与「忌口词全部在 JSON 里」这一单一事实源要求不冲突——**排除词一条都不在代码里**。该补充已通过 §8-3b 验证。

### 4.2 存疑区的保留（§6.4 教训的正式化）

`steps`/`tips` 命中忌口词时**保留**并打印复核清单，不静默放行。实测 5 道，逐条人工看原文后判定**全部保留**：

| 菜名 | 命中 | 原文 | 判定 |
|---|---|---|---|
| 腐乳肉 | `steps:鱼` | 步骤 7「看到汤汁冒浓稠**鱼眼泡**时关火」 | 保留：火候术语，与鱼无关 |
| 椒盐排条 | `tips:鱼` | tips「炸糊也可以用来炸鸡腿、**炸鱼**等」 | 保留：说炸糊的通用用途 |
| 蒸水蛋 | `tips:鱼` | tips「也可加入**蒸鱼**豉油」 | 保留：调料名，可选佐料 |
| 酱拌荞麦面 | `tips:虾`/`虾仁` | tips「配料可以……例如**虾仁**、肉沫等」 | 保留：可选配料建议 |
| 煮泡面加蛋 | `tips:鱼`/`虾`/`虾仁` | tips「可加入……**鱼干、虾仁**、鸡腿」 | 保留：可选配料建议 |

> 后 3 道均为 `staple`（不进随机池）；椒盐排条在用户白名单内。**未私自扩大排除表。**

### 4.3 蛋白池软告警阈值随白名单切换

`protein.length < 20` 是「池子过小」软告警。白名单启用后荤菜池=84，若沿用 20 会失去意义；改为 **`<15` 告警**（出处：白名单设计下限，规划 §5.4 / 需求梳理 §4.1 组合数表；`<4` 已在校验集硬失败）；`启用:false` 时维持 `<20` 原语义。这是**功能性阈值**（够不够出餐 / 会不会吃重复），不是「当前数量」断言，加菜不受影响。
