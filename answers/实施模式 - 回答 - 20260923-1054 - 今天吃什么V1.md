## 5. 关键技术决策与理由

### 5.1 数据源：只取 HowToCook 的文字

上游 371 篇 markdown，本项目只提取菜名、食材用量、做法步骤、小贴士、来源链接，**不下载图片**。上游图片托管在境外 CDN，与"国内家庭网络可用"的硬要求冲突；且需求明确图片不是核心依赖。

### 5.2 菜谱数量：370 道，未达 1000～3000 目标

上游 HowToCook 公开的高质量中文菜谱总量就是 371 篇（去重后 370）。需求已预先说明"如果无法一次完成目标，不要虚构数据、不要为凑数复制低质量数据，先完成真实子集并说明缺口"，因此按真实数据交付，缺口写入 README 与最终报告。

### 5.3 menuRole 用人工复核表，而非规则推断

上游按「荤菜 / 素菜」分目录，但家常菜里**鸡蛋、豆腐、豆类同属蛋白质来源**，部分肉汤也实际是正经菜。若按目录机械映射，会出现「西红柿炒鸡蛋」被归为素菜这类语义错误。

因此在 `tools/build-recipes.mjs` 中维护了一张 `ROLE_OVERRIDE` 人工复核表，逐条纠正跨类菜品。

### 5.4 两类菜被有意排除出随机池

- 「完美水煮蛋 / 温泉蛋 / 溏心蛋 / 微波炉荷包蛋 / 太阳蛋 / 茶叶蛋 / 鸡蛋花 / 朱雀汤」——确实提供蛋白质，但抽到「溏心蛋 + 蒜蓉西兰花」不像一顿正经晚饭，属于会让用户以为程序出错的组合。
- 「水煮玉米」——是加餐/主食，不是一道素菜。

它们完整保留在数据文件中（`menuRole` 标为 `breakfast` / `dessert` / `staple`），只是不参与「一荤一素」的随机。

### 5.5 装饰动效不得影响内容可见性

验证中发现宿主内置浏览器环境**不推进 CSS 动画时钟**（`document.getAnimations()` 所有动画 `currentTime` 恒为 0）。这暴露了一个真实风险：原先的入场动画写在关键帧 `from { opacity: 0 }`，一旦动画因省电模式、后台标签页等原因被中断，卡片和详情面板会**永久不可见**。

修正为：入场动效只做位移、不做透明度；遮罩层的整体淡入动画直接移除（它的 `opacity` 作用在包含面板的容器上，中断会让整个详情消失）。

最坏情况从"内容全白"降级为"偏移几个像素"。

### 5.6 本地运行方式

浏览器禁止 `file://` 页面读取本地 JSON，直接双击 `index.html` 会失败。因此提供零依赖的 `node tools/serve.mjs`，并在页面上对 `file://` 协议做显式检测，直接告诉用户该怎么做，而不是留一个空白页。

## 9. 未验证风险

1. **数据规模缺口**：370 道 vs 目标 1000～3000 道。补齐需要找到版权和质量都可控的中文菜谱源，目前没有第二个可靠来源。
2. **上游内容质量参差**：HowToCook 是社区贡献项目，个别菜谱的步骤粒度差异较大（2 步到 20 步都有）。已过滤掉步骤少于 2 条的异常项，但未逐条人工审校全部 370 道。
3. **CloudBase CLI 版本差异**：部署命令基于本机 2.12.2 实测语法，其他版本可能有出入。
4. **蔬菜池偏小**：42 道素菜的重复率会明显高于 188 道的蛋白池。这是上游数据分布决定的，不是实现缺陷。
